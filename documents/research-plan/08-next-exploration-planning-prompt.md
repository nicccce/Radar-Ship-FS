## 二、必须准确继承的事实

- 当前主要数据为 `v16n_2x_noise`：source-train 3897 行，原始 75 列，当前清洗后 65 列。真实场景、增强父样本与环境映射没有恢复。
- 任务 3 发现了 DT 搜索目标与 LR 评价的失配，也证明旧动作池遗漏有效路径；4A 修复了动作支持，但没有证明学习策略的性能优势。
- 4B 的 LR Balanced Accuracy 诊断评分器通过候选银行可靠性门槛；整体 NO-GO 是因为 K=16/32 的联合搜索增益要求未同时满足。不能将其解释成“奖励完全没有信息”。
- 4C 只检查了 `K=32 + 固定 LR 评分器 + forward 初始化 + 最多两轮完整 single-swap`。outer 平均提升为 0.1009 个百分点，3 正、2 平、0 负，未达原门槛。前三折受两轮预算限制，后两折第一轮无严格改善。
- 4C 没有训练 RL，也没有证明全局最优、所有多步路径无收益或所有其他 K/目标均无机会。旧分支的停止决定保持有效。
- 3A/任务 7 的阻断来自真实 group/env 等数据前提，任务 7 没有比较条件化方法。它们不能禁止所有不依赖这些字段的算法机制探索。
- 4C 开发结果中，All Features 的 LR BAcc 为 91.8579%，32 维 forward+swap 为 91.6751%。这不构成非劣或泛化证明；减少维数也不自动意味着减少真实特征提取成本。
- 旧 source-test 已反复使用；历史 outer-development folds 也参与过研究决策。更换 seed 或重分折不会使同一数据重新成为独立确认数据。
- DFS 的历史可比结果缺少可追溯性。可另行提出正规重建的最小方案，但不能填造旧成绩，也不能未经辨认就把所有可微特征选择方法都叫作同一个 DFS。

## 三、重新判断研究目标，不机械继承旧门槛

原先“强贪心附近能否再提升 0.2 个百分点”的门槛回答的是某条局部精度路线是否值得扩大投入。请区分以下问题：

1. 在同一预算下能否找到更好的子集？
2. 能否用更少评价次数和总时间达到同等质量？
3. 通过多个训练实例学到的搜索策略，能否在新实例上复用并摊销训练成本？
4. 是否存在被当前评价器遗漏、且能在相应下游任务上验证的特征交互？
5. 原始显式融合目标是否适合研究可学习的组合优化？

旧 4C 的门槛不是这些问题共同的必要条件。允许提出有新机制、新比较目标的新探索；保留旧结果，不通过降低旧门槛、挑有利 folds、扩大扫描直到过关来重新宣布旧任务成功。

也不要先规定 RL 必须获胜。对于同一数据集的一次性静态搜索，必须认真比较简单算法的成本；对于跨实例学习，要交代真实任务分布和复用需求。选择表现更好的非 RL 方法是允许的结论，但要明确它是否符合用户希望保留 RL 的研究定位。

### A. 搜索效率与可复用的候选排序

假设：现有 exhaustive forward/swap 的大量评分可能可以由便宜的筛选、代理排序或搜索策略减少；贡献可以是达到相近质量时的总成本降低，而非强起点之后再涨固定精度。

- 先核对已有耗时。LR 评分本来可能很便宜；若训练一个策略更贵，要明确机会可能不成立。
- 候选对照包括固定 MI/相关性排序、预算匹配的随机候选、sampled greedy、多起点或轻量代理。根据首个问题选少量最有区分力的对照，不做算法大赛。
- 说明新问题与关闭的旧 5A/5B 的区别：例如从弱起点构建、全过程评价效率、不同任务实例上的复用；仅更名继续旧强起点实验不算新假设。
- 旧候选银行可用于开发诊断，不能据此把只在该银行内重放的排名结果解释成在线搜索优势。银行未覆盖的动作、状态和请求如何处理必须说明。
- 比较必须包含初始化、训练标签生成、代理/RL 训练、特征统计计算、搜索请求、实际拟合和墙钟时间。缓存策略与并行资源一致。
- 若主张跨实例摊销，列出训练/开发/测试任务的真正分离单位，并报告 `T_train + M × T_infer` 对比 `M × T_baseline` 的适用条件。重叠数据上的多个 seed/folds 不能直接冒充独立任务。

### B. 非线性交互与评价器适用范围

假设：在 LR 下收益有限，不代表对所有合理的下游识别器都没有价值；但必须先看到可验证的交互机会。

- 利用已有 LR/DT 分歧，判断它更像评价错配、方差，还是有待研究的非线性交互。不要凭“有非线性”就断言需要 RL。
- 若值得试，只选一个有理由的非线性评价器并固定小规模配置，选择与评价使用一致目标；全特征、简单筛选、贪心都用相同下游模型。
- 若把学习式方法纳入后续比较，须包括一个可追溯的可微选择强基线。先辨认仓库所指 DFS 的论文与实现；其他方法以自身名称报告。
- 合成的交互正例和无交互负例可以检验机制，必须保留简单非 RL 对照。不得只构造有利于 RL、故意令 LR 或贪心失败的数据，然后宣称解决雷达任务。
- 当前数据可用于明确标注的探索性比较；场景泄漏风险未知，不能把结果称为跨场景泛化。

### C. 回到 problem.md 的显式融合目标，研究跨实例组合优化

原问题定义：

`F(S,e) = 1 - product((1 - mu_i(e)) ** gamma for i in S)`

`gamma = (1 - mean_abs_correlation(S)) ** (|S| - 1)`，约束为 `|S| <= K`。

- 先检查目标的边界定义、数值饱和、单调性和可变子集大小；空集、单元素、完全相关及 mu 接近 1 时必须有明确定义。不要未经说明把“至多 K”换成“恰好 K”。
- 检查是否能用保持排序的等价数值表达计算目标，以及简单优化方法是否已足够。若目标本身不适合作为融合性能假设，明确说明，不为配合 RL 悄悄改公式。
- 可以设计有合法相关矩阵的可控实例分布，通过小 N 的穷举获得最优解参照；更大 N 使用强启发式并诚实标注最优性未知。
- 比较高均值选择、贪心、局部搜索/多起点中的必要对照。RL 若进入后续研究，应学习跨实例策略，评价未见实例上的最优差距、时间和训练成本。
- 训练、开发、测试实例应由可追溯且预先指定的生成过程产生；报告完整参数范围和所有预定难度，不按 RL 胜负挑实例。
- 显式目标的好成绩只证明对该数学目标的优化能力。其物理合理性以及与真实雷达识别的关系需要另证，不能把 F 当作实测分类准确率。
- 判断这是否符合用户原始研究定位，并比较它与在当前 65 维数据上继续训练的投入价值。

环境条件化、逐样本特征获取可以作为更远期方向，但需真实环境输入或可解释的获取成本。缺少这些条件时，不把它们列为唯一的当前行动，也不重复运行任务 7。
