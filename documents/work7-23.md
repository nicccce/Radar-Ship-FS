# 雷达舰船强化学习特征选择阶段性工作汇报大纲

> 建议汇报时长：5～8 分钟。  
> 汇报主线：**数据集准确率已接近天花板，单看 Accuracy 很难区分方法；强化学习的价值主要体现在“保持性能的同时压缩特征”，并且新增的特征数量约束已经能够把子集控制到目标预算内。**

## 1. 工作目标与已完成内容

### 汇报要点

- 基于 `interactive-rl-feature-selection` 框架完成雷达舰船数据接入。
- 已完成三类强化学习方法：
  - MARLFS；
  - Full-IRFS-fixed；
  - Full-IRFS-trained-GCN。
- 以 Decision Tree 作为强化学习搜索反馈和最终统一检测器。
- 完成 5 个随机种子的主实验，并补充 β、指导比例和特征数量惩罚实验。
- 新增特征数量约束，使强化学习输出能够满足 `k≤27` 的预算要求。

### 实验设置（简单带过）

- 数据规模：2304 个样本、54 个候选特征。
- 每个随机种子划分为 1843 条 development 和 461 条独立 test。
- 强化学习只在 development 内使用固定 5 折 DT Accuracy 进行搜索。
- 每种方法每个 seed 搜索 250 步，主实验使用 seeds 42～46。
- 最终子集冻结后，统一在独立 test 上使用 Decision Tree 检测。

### 对比方法分别是什么

#### 1. All Features

- 不进行特征选择，直接使用全部 54 个特征训练 Decision Tree。
- 作用是提供“完全不筛选”的性能基准，用来判断减少特征后是否损失检测能力。

#### 2. KBest/MI，也就是 TopK

- 先在 development 数据上计算每个特征与类别标签之间的互信息（Mutual Information，MI）。
- 按 MI 分数从高到低排序，直接选择排名前 \(k\) 的特征。
- 主实验固定 `k=27`，所以也记作 **MI-27** 或 **Top-27**。
- 它不使用强化学习，不考虑特征之间的组合搜索，是一个计算简单、速度快的传统 Filter baseline。
- 它的意义是回答：复杂的 RL 搜索是否能够超过“直接选择与标签最相关的 27 个特征”。

可以用一句话解释：

> TopK 就是先给每个特征单独打分，再直接取分数最高的前 27 个；它速度快，但不直接优化多个特征组合后的整体效果。

需要注意，Hybrid Teaching 中的 MI relevance advisor **不等于 Top-27**：advisor 只能阻止部分高 MI 特征被过早删除，不能主动补齐 MI 排名前 27 的特征，也没有固定 `k=27` 的约束。

#### 3. MARLFS

- MARLFS 是基础的多智能体强化学习特征选择方法。
- 每个特征对应一个智能体，每个智能体负责决定自己的特征是 `Select` 还是 `Deselect`。
- 所有智能体的动作合并后形成一个候选特征子集，再用 5 折 Decision Tree Accuracy 评价这个组合。
- 智能体根据 DT 反馈不断更新选择策略，目标是搜索到整体检测效果较好的特征组合。
- 当前实现使用较简单的 relevance/redundancy 状态，不包含外部 Trainer 和可训练 GCN。

可以用一句话解释：

> MARLFS 不是分别给特征打一次分，而是让每个特征智能体反复试验保留或删除，通过 DT 的整体检测结果学习哪些特征应该共同出现。

#### 4. Full-IRFS-fixed

- 在 MARLFS 的多智能体框架上加入完整的交互式强化学习机制。
- 使用 Hybrid Teaching：
  - 前一阶段由 MI relevance 规则提供指导；
  - 中间阶段由 Decision Tree 特征重要性提供指导；
  - 后一阶段撤回指导，由智能体自主搜索。
- Decision Tree 不只提供 Accuracy，还参与特征重要性反馈和个性化奖励分配。
- `fixed` 表示图状态聚合使用固定权重，不训练额外的 GCN 参数。

可以用一句话解释：

> Full-IRFS-fixed 在基础 RL 上增加了 MI 和决策树教师，让智能体在搜索早期少走弯路，但状态编码本身采用固定计算方式。

#### 5. Full-IRFS-trained-GCN

- Trainer、Decision Tree 反馈、奖励和搜索流程与 Full-IRFS-fixed 基本相同。
- 主要区别是使用可训练 GCN 编码当前特征子集的图结构。
- 图中的节点表示特征，边表示特征相关性以及 Decision Tree 提取出的结构关系。
- GCN 通过训练学习如何聚合这些关系，再把得到的状态表示提供给各个特征智能体。
- 目的是检验：可学习的图状态是否比固定图聚合更有利于特征组合搜索。

可以用一句话解释：

> trained-GCN 版本让模型自己学习特征之间的图关系如何编码，表达能力更强，但训练成本也明显更高。

#### 6. 加入特征数量约束的 Full-IRFS

- 基础结构仍采用 Full-IRFS-fixed。
- 在 Accuracy 和相关性奖励之外，增加超过 27 个特征时的惩罚项。
- 最终只允许 `|S|≤27` 的候选成为输出，目标从“只找高准确率子集”变为“在 27 个特征预算内找高准确率子集”。
- 该版本属于本项目在原有方法上的扩展，用来解决 RL 容易选择过多特征的问题。

### 方法之间的递进关系

```text
All Features
    └─ 不做筛选的检测基准

KBest/MI-27
    └─ 单特征打分后直接取 Top-27 的传统筛选基准

MARLFS
    └─ 每个特征一个智能体，利用 DT 整体反馈搜索特征组合
         └─ Full-IRFS-fixed
              └─ 增加 Hybrid Teaching、树结构反馈和个性化奖励
                   └─ Full-IRFS-trained-GCN
                        └─ 将固定图状态替换为可训练 GCN

本项目扩展：Full-IRFS-fixed + 特征数量惩罚 + k≤27 候选约束
```

## 2. 先展示核心现象：各方法准确率都很高

### 建议主表

| 方法 | 平均特征数 | 特征压缩率 | DT Test Accuracy |
|---|---:|---:|---:|
| All Features | 54.0 | 0% | 0.9618 ± 0.0076 |
| KBest/MI | 27.0 | 50.00% | **0.9679 ± 0.0074** |
| MARLFS | 27.2 ± 3.2 | **49.63%** | 0.9618 ± 0.0054 |
| Full-IRFS-fixed | 34.8 ± 4.2 | 35.56% | 0.9657 ± 0.0110 |
| Full-IRFS-trained-GCN | 36.4 ± 2.1 | 32.59% | 0.9675 ± 0.0077 |

### 建议重点讲的数据

- 所有方法的平均 DT test Accuracy 集中在 **0.9618～0.9679**。
- 最好与最差平均值只差 **0.0061，即 0.61 个百分点**。
- test 只有 461 个样本，1 个样本约对应 0.217 个百分点；0.61 个百分点实际只相当于约 3 个样本。
- 所有方法的 DT 训练准确率均为 1.0000，说明决策树很容易把 development 数据拟合满。

### 建议图

使用“横轴为平均特征数、纵轴为 DT Test Accuracy”的散点图：

- All Features 放在最右侧；
- MARLFS、Full-IRFS-fixed、Full-IRFS-trained-GCN 使用同一颜色系；
- KBest 使用灰色作为传统方法参照；
- 纵轴可放大到 0.94～0.98，但必须注明“纵轴已截断”，避免视觉夸大差异。

### 推荐表述

> 当前数据的可分性较强，不论保留全部特征、使用传统方法，还是使用不同强化学习方法，Decision Tree 的测试准确率都在 96%～97% 左右。各方法之间的差距只有零点几个百分点，小于或接近不同随机种子带来的波动，因此当前数据很难仅通过 Accuracy 拉开算法差距。

## 3. 强化学习是否有效：从“准确率—特征数”联合评价

### 可选择性重点展示的三组结果

| 对比 | 特征变化 | DT Accuracy 变化 | 可以说明什么 |
|---|---:|---:|---|
| All Features → MARLFS | 54 → 27.2，减少 49.63% | 0.9618 → 0.9618 | 减少近一半特征，平均准确率不下降 |
| All Features → Full-IRFS-fixed | 54 → 34.8，减少 35.56% | 0.9618 → 0.9657 | 压缩特征的同时维持同一准确率水平 |
| All Features → Full-IRFS-trained-GCN | 54 → 36.4，减少 32.59% | 0.9618 → 0.9675 | 当前 RL 方案中的最高平均 DT 准确率 |

### 推荐结论

> 如果只比较 Accuracy，很难证明某一种强化学习结构显著优于其他方法；但从“使用更少特征并保持检测性能”的目标看，强化学习是有效的。MARLFS 在减少约 50% 特征后仍保持与全特征相同的平均准确率，Full-IRFS-trained-GCN 在减少约 33% 特征后达到 0.9675 的平均准确率。

### 必须保留的边界

- 不表述为“RL 全面优于传统方法”，因为 KBest-27 的平均 DT Accuracy 为 0.9679，仍略高于当前 RL。
- 不表述为“trained-GCN 显著优于 fixed”，目前差值较小，且标准差重叠。
- 更准确的结论是：**RL 已验证为可用的特征压缩方案，但尚未证明在预测准确率上稳定优于简单 KBest。**

## 4. 为什么各种 DT 方案都差不多

### 原因判断

1. **数据任务偏容易。** 多种不同子集都能达到 96%～97%，已经接近当前评价协议下的性能天花板。
2. **特征之间存在较强冗余。** 删除一部分特征后，剩余特征仍然能提供足够的类别信息。
3. **Decision Tree 容易过拟合。** 所有方案的 development 训练准确率都是 1.0000，而 test 的小幅差别会受划分和树结构高方差影响。
4. **测试集规模有限。** 不同方法平均只差约 2～3 个预测样本，难以形成稳定排序。

### 推荐表述

> 目前更主要的问题不是算法完全无效，而是数据对不同特征选择方法的区分能力不足。用 DT 检测时，各种子集都能取得很高准确率，方法间差异容易被随机划分和决策树自身波动覆盖。因此，本阶段应把“是否能在不损失性能的情况下减少特征”作为主要评价目标，而不是强调零点几个百分点的 Accuracy 排名。

## 5. 新增 loss 特征数量约束：已经实现预算控制

### 方法

在原有 Accuracy 和相关性项之外，增加超过 27 个特征时的惩罚：

\[
J(S)=Accuracy_{CV}(S)-0.02\,Corr(S)
-\lambda\max\left(0,\frac{|S|-27}{27}\right)
\]

实现中同时将最终输出限制为 `|S|≤27` 的候选，从而使搜索阶段可以探索超预算子集，但最终结果必须满足特征预算。

### 建议只在主汇报展示最佳配置

同为 seeds 42～45：

| 配置 | 平均特征数 | DT Test Accuracy | 说明 |
|---|---:|---:|---|
| 约束前：β=0.02 | 34.50 ± 2.38 | 0.9675 ± 0.0077 | 子集规模仍明显超过 27 |
| 约束后：β=0.02、λ=0.025 | **25.50 ± 1.29** | **0.9680 ± 0.0045** | 平均少 9 个特征，准确率基本不变 |

### 可以强调的数据

- 平均特征数由 34.5 降至 25.5，减少约 **26.1%**。
- 相对原始 54 个特征，最终只保留 25.5 个，整体压缩约 **52.8%**。
- DT Test Accuracy 没有下降：0.9675 → 0.9680。
- 与 MI-27 的逐 seed 对比为 **2 胜、1 平、1 负**；平均准确率仍比 MI-27 低 0.0016。

### 推荐结论

> 我进一步在目标函数中加入了超预算惩罚，并配合预算内候选筛选。最佳 λ=0.025 时，平均特征数从 34.5 降到 25.5，同时 DT 测试准确率仍保持在 0.9680，说明特征数量约束已经生效，强化学习能够在给定预算下找到有效子集。

### 诚实说明

- “成功”指的是**成功控制特征数量，同时保持当前 DT 性能水平**。
- 不能写成“仅靠 loss 惩罚就能稳定生成固定规模子集”，因为最终结果还使用了预算内候选筛选。
- λ 的效果不单调，只有 `λ=0.025` 在本轮取得较好的特征数—准确率平衡；其他 λ 结果放在附录，不在主线展开。

## 6. 阶段性结论

### 建议用三句话收束

1. **数据层面：** 当前数据在 DT 上可分性过强，多数方法都能达到 96%～97%，准确率存在明显天花板效应，难以用零点几个百分点区分方法。
2. **算法层面：** 强化学习总体有效，主要表现为减少约 33%～50% 的特征后仍保持与全特征相当的 DT 检测性能。
3. **改进层面：** 新增超预算惩罚和预算内候选筛选后，平均特征数成功降到 25.5，DT Accuracy 维持在 0.9680，证明特征数量目标是可以显式控制的。

### 一段式汇报口径

> 本阶段已经跑通了 MARLFS 和两种 Full-IRFS，并完成多随机种子测试。当前数据本身比较容易分类，各种方法在 Decision Tree 上都能达到 96%～97%，最好和最差平均只差 0.61 个百分点，因此很难单靠准确率拉开差距。更有意义的结果是，强化学习能够在减少约三分之一到一半特征的情况下保持相同水平的检测准确率。进一步加入特征数量惩罚并限制最终候选预算后，平均特征数从 34.5 降到 25.5，而 DT Accuracy 仍维持在 0.9680。因此可以认为强化学习特征选择总体有效，且特征数量约束已经实现；但目前还不能声称它在准确率上稳定超过 KBest。

## 7. 下一步工作

- 排查数据中是否存在重复样本、近重复样本、同源样本或过强的仿真模式。
- 尝试按来源、场景或目标分组划分，而不只使用随机分层划分。
- 增加更能拉开差距的指标，如 Macro-F1、Balanced Accuracy、Recall 和 ROC-AUC。
- 在更多或更难的数据集上复验，判断 RL 的压缩能力是否稳定。
- 将当前“软惩罚 + 最终预算过滤”进一步改成固定预算搜索：
  - 每步动作后执行 `k=27 repair`；或
  - 使用一进一出的特征交换动作。
- 补充运行时间分析：trained-GCN 每个 seed 约 1094.6 秒，明显高于 fixed 的约 139.8 秒，需要评价额外计算是否值得。
